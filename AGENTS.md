
# FEFU Checker (`fefu-checker`) — Instructions for AI Agents

## 1. Project Overview
`fefu-checker` — это легкий клиентский веб-инструмент (Single File Web App), который помогает абитуриентам Дальневосточного федерального университета (ДВФУ / FEFU) отслеживать свою позицию в конкурсных списках поступления.

Все данные загружаются напрямую с публичного API ДВФУ.

---

## 2. Technical Stack & Architecture
* **Single File Architecture:** Весь код (HTML, CSS, JS) должен располагаться в **одном файле** `index.html`.
* **No Heavy Dependencies:** Чистый JavaScript (Vanilla ES6+), чистый CSS (или подключение стилей через CDN, например Tailwind CSS / Pico.css).
* **No Build Tools:** Проект должен запускаться путем открытия `index.html` в любом браузере или через простой локальный сервер (`live-server`, `python -m http.server` и т.д.).

---

## 3. Data Source & API Specification

### Base API Endpoint
`https://www.dvfu.ru/admission/spd/api/admission-list`

### Query Parameters
| Параметр | Значение по умолчанию / Пример | Описание |
| :--- | :--- | :--- |
| `campaignType` | `БВО / бакалавриат / специалитет` | Тип кампании |
| `financingSource` | `Бюджет` / `Договор` | Источник финансирования |
| `studyForm` | `Очная` / `Заочная` / `Очно-заочная` | Форма обучения |
| `trainingDirection` | `09.03.04 Программная инженерия` | Код и наименование направления |
| `sort` | `BySum` | Сортировка (обычно по сумме баллов) |
| `topPriority` | `true` / `false` | Высший приоритет |
| `atestOrig` | `true` / `false` | Фильтр оригиналов аттестатов/дипломов |
| `enrolled` | `false` | Зачисленные |
| `highPriorityNoOriginal` | `false` | Высокий приоритет без оригинала |
| `approval` | `false` | Согласия |
| `excludeBudgetEnrolled` | `false` | Исключить зачисленных на бюджет |
| `contract` | `false` | Договор |

### CORS Notice
* API ДВФУ может блокировать прямые кросс-доменные запросы (CORS) из браузера.
* **Требование:** Реализовать логику так, чтобы при возникновении ошибки CORS приложения предлагало либо использовать публичный CORS-прокси (например, `https://corsproxy.io/?`), либо выводить подсказку пользователю.

## 4. Key Functional Requirements

1. **Форма ввода / Настройки:**
   * Поле ввода **Кода и названия направления** (например, `09.03.04 Программная инженерия` или просто `09.03.04`). Предусмотреть пресеты популярных направлений (09.03.04, 09.03.01, 09.03.03 и др.).
   * Поле ввода **ID абитуриента / СНИЛС** (по какому значению ищется кандидат в полученном от API списке).
   * Селекторы параметров: Форма обучения (`Очная`), Источник финансирования (`Бюджет`/`Договор`), Опции приоритета (`topPriority=true/false`).

2. **Обработка данных & Аналитика:**
   * Запрос к API ДВФУ по переданным параметрам.
   * Поиск пользователя по ID / СНИЛС в массиве поступивших данных.
   * Расчет метрик:
     * Абсолютная позиция в списке.
     * Позиция среди подавших **оригинал** документов (`atestOrig = true`).
     * Количество человек перед пользователем, подавших оригинал.
     * Общее количество бюджетных мест (если API передает эти данные или задается вручную).

3. **Отображение результатов:**
   * Карточка статуса: найден ли абитуриент, его текущая позиция, балл, наличие оригинала, приоритет.
   * Подсвечивание строки пользователя в общей таблице (если выводится весь список).
   * Сохранение последних введенных данных в `localStorage` браузера для удобства повторных визитов.

## 5. UI / UX Guidelines
* **Mobile First:** Интерфейс должен быть полностью адаптирован под мобильные устройства (смартфоны).
* **Состояния (States):**
  * *Loading:* Идикатор загрузки при отправке запроса.
  * *Success:* Вывод аналитики и таблицы.
  * *Not Found:* Понятное сообщение, если ID не найден в выбранном направлении.
  * *Error:* Сообщение об ошибке (проблемы с сетью, CORS, неверные параметры).
* **Стиль:** Современный, минималистичный, адаптивный (Dark/Light mode приветствуется).

---

## 6. Rules for AI Agents Working on This Codebase

1. **Не разбивать код на несколько файлов.** Весь HTML, CSS и JS строго в `index.html`.
2. **Безопасность:** Не хардкодить чувствительные данные (хотя API публичный).
3. **Обработка ошибок:** Каждая операция `fetch()` должна быть обогнута в `try...catch` с выводом человекочитаемой ошибки в UI.
4. **Валидация:** Форматировать СНИЛС / ID пользователя (удалять лишние пробелы и тире при поиске, если формат в API отличается).
5. **Тестируемость:** Код должен быть чистым, с понятными названиями функций (`fetchAdmissionList`, `findApplicant`, `renderResults`, `saveToLocalStorage`).
